# ADR-001: Self-hosting layout for `packages/s0ma-mcp` (FR-MCP-11)

**Status:** Accepted.
**Date:** 2026-06-10 (selfhost plan SH-M1).
**Context:** `plans/s0ma-new-mcp-selfhost-1.md` M1; PRD v1.3 §7.3 FR-MCP-11, §5 P-4, §6 INV-5/INV-2/INV-8; M0 hand-off notes F-M0-1, F-M0-6, F-M0-7, F-M0-8 (`plans/notes/mcp-selfhost-friction-log.md`); s0ma-dsl ADR-005 (project discovery), ADR-006 (canonical module identity), ADR-007 (single flat build layout).

---

## Decision 1 — Layout: **L2**, the build output is a generated subpackage at `src/s0ma_mcp/_built/`

`packages/s0ma-mcp` becomes a `[tool.s0ma]` project with this shape:

```
packages/s0ma-mcp/
    pyproject.toml              # [tool.s0ma]: source_roots=["s0ma_src"], build_dir="src/s0ma_mcp/_built", mode="dev"
    s0ma_src/                   # the .s0ma sources (the things humans/agents edit)
        resources.s0ma
    src/s0ma_mcp/               # the importable package (handwritten shell, shrinking per D-1)
        __init__.py             # handwritten: __version__, bootstrap_imports(_built), sys.modules aliasing, catalog bridge
        _built/                 # the committed transpiler output — generated, never hand-edited
            __init__.py         # auto-emitted by `s0ma build` (the generated-marker docstring)
            build.s0ma.json     # build manifest (committed; deterministic after Decision 2)
            build.s0ma.pyi      # typed bootstrap stub (committed; deterministic)
            resources.py        # emitted module + IR + source map (committed)
            resources.s0ma.json
            resources.s0ma.map
        components.py … tools.py  # handwritten survivors (M2/M3 convert them away)
        _docs/, py.typed        # non-Python package data, unchanged
```

The committed `_built/` tree ships in the wheel exactly as committed (hatchling packages everything under `src/s0ma_mcp`; the regenerable `.s0ma.cache/` is gitignored and excluded from the wheel). The committed-build equality stage in `scripts/check.py` (`selfhost-build`) rebuilds `_built/` from `s0ma_src/` with the cache disabled on every CI run and fails on any byte difference.

### Runtime import identity: flat canonical names via `bootstrap_imports`, aliased into the package namespace

The DSL's runtime contract for built modules is the **flat** module name with `build_dir` on `sys.path`: `bootstrap_imports(build_dir)` reads `build.s0ma.json`, inserts `build_dir` at the head of `sys.path`, and imports each module by its canonical name in `topological_import_order`. Emitted cross-module imports are flat top-level (`from resources import load_doc`), so the flat identity is the only identity under which a multi-module build can execute. The package therefore adopts the product's own bootstrap pattern from M1, not a hand-rolled loader: `s0ma_mcp/__init__.py` calls `bootstrap_imports(Path(__file__).parent / "_built")`, binds each built module as a package attribute, and aliases it into `sys.modules` under its dotted name (`sys.modules["s0ma_mcp.resources"] = <module 'resources'>`). One module object, executed exactly once (registrations fire once), reachable as both `resources` (the DSL's canonical identity) and `s0ma_mcp.resources` (the package identity every existing import form and test uses). This is precisely the mechanism M0's spike shim proved through the in-process MCP boundary, now landed as the package's real wiring; it is also the seed of M4's single bootstrap module — FR-MCP-11's end state — which will do the same `bootstrap_imports` call and derive the FastMCP surface from the registrations it triggers.

For mypy (`--strict` over `src/s0ma_mcp`, D-2), the emitted code is part of the package walk (`s0ma_mcp._built.resources`) and is type-checked under the same gate as handwritten code. Handwritten code gets real types for built symbols via the static identity: `if TYPE_CHECKING: from s0ma_mcp._built import resources as resources; else: resources = <bootstrap result>`. The static path (`s0ma_mcp._built.resources`) and the runtime path (flat `resources`) are the same file, so the types are sound; the dotted path must never be imported at runtime (it would execute the module a second time and double-register — the `__init__` docstring and this ADR are the guard rails). Known consequence, accepted: external type-checkers cannot resolve `import s0ma_mcp.resources` statically (the alias is runtime-only); the package's typed public surface is `create_server`/`main`, and nothing outside this repo imports the converted modules as libraries.

**M2+ note (the flat view under mypy):** once a second `.s0ma` module lands and emitted flat cross-imports appear (`from resources import load_doc` inside `_built/tools.py`), a single package-rooted mypy walk cannot resolve them (no top-level `resources` in the package view) and adding `_built` to `mypy_path` would create duplicate module identities. The decided shape for that milestone: exclude `_built/` from the package-rooted mypy invocation and add a second strict invocation over `_built/` as flat top-level modules (`MYPYPATH=_built`, targets `_built/*.py`), keeping D-2 (every emitted file strict-gated) as a two-invocation gate. M1 needs only the single invocation (one module, no flat cross-imports) and keeps it.

### Why L1 (build_dir = `src/s0ma_mcp`, "the package IS the build output") was rejected

Three constraints in the build machinery are fatal to L1, read directly from the code:

1. **The auto-emitted `__init__.py` owns the build root.** `_emit_build_init` (`s0ma_dsl/cli/main.py`) overwrites any `build_dir/__init__.py` whose content differs from the canonical generated-marker docstring — "mismatched content is overwritten so a stale or hand-edited file cannot silently shadow the canonical docstring". Under L1 the package's handwritten `__init__.py` (which must carry `__version__`, the package docstring, and — under this ADR — the bootstrap call itself) is clobbered on every build. There is no `package_markers`/`bootstrap_files` escape: those lists classify files for `s0ma verify`, they do not stop the build's init emission. The one file FR-MCP-11's end state still needs handwritten logic in is the one file L1 hands to the generator.
2. **Emitted flat cross-module imports poison the package namespace.** With build_dir = the package dir, the only way emitted `from resources import x` resolves is `src/s0ma_mcp` itself on `sys.path` — at which point every module is importable both as `s0ma_mcp.x` and as `x`: two module objects per file, doubled `@component`/`register_*` execution, and mypy's "source file found twice under different module names" hard error. L2 confines the dual identity to a controlled alias of a single module object.
3. **Generated/handwritten ownership has no boundary.** Under L1, orphan pruning (`_prune_orphan_artefacts`), `verify` classification, the equality gate's compare set, the wheel's "ships exactly as committed" claim, and gitignore/cache anchoring (`.s0ma.cache/` anchors inside build_dir) all need allowlists distinguishing generated from handwritten files inside one directory — every list a drift surface. L2 makes the boundary a directory: everything under `_built/` is generated and byte-gated; everything beside it is handwritten and shrinking (D-1). The plan's own risk register anticipated exactly this: "Build-dir ownership fights handwritten survivors … L2 layout exists precisely as the safe fallback."

The price of L2 — one extra path segment in the committed tree and the runtime aliasing block in `__init__.py` — is the entire cost. The aliasing block is part of M4's single bootstrap module anyway; M1 just grows it in `__init__.py` until M4 consolidates.

### `[tool.s0ma]` wiring and the bootstrap_files inventory

`mode = "dev"` (D-6: the mode ramps `dev` → `strict` (M3) → `release` (M5); the table key is declarative today — the CLI's `--mode` flag carries the operative value, so the equality stage and authors pass `--mode dev` explicitly). `source_roots = ["s0ma_src"]`, `test_roots = ["tests"]` (disjoint, G2), `build_dir = "src/s0ma_mcp/_built"` (basename is a valid identifier, G3). `bootstrap_files` declares the five handwritten package modules — `src/s0ma_mcp/__init__.py`, `components.py`, `prompts.py`, `server.py`, `tools.py` — so `s0ma verify` classifies them `BOOTSTRAP`, and the list is itself the D-1 burn-down inventory: M2 removes `prompts.py`, M3 removes `tools.py`, M4 collapses `components.py`/`server.py` into the single bootstrap module. Handwritten-module count after M1: **5** (was 6; `resources.py` is deleted, replaced by `s0ma_src/resources.s0ma` + the committed build). All `s0ma`/`s0ma build` invocations in scripts pass `--project-root packages/s0ma-mcp` (F-M0-1: discovery anchors on CWD, not the path argument).

### Self-model continuity during the conversion (M1–M3 transition mechanics)

The built module's emitted registrations target the **process-global** registry (core `@component` + `s0ma_dsl.runtime_bridge` `register_*` calls) under DSL identifier names — that is the product's runtime model and it now happens in this package's own process at import. The package self-model (`components._CATALOG` → `get_self_registry()`, FR-MCP-7/D-6) absorbs the converted surface through a small generic bridge in `components.py`: for each built-module member carrying `__component__`, the bridge looks up the component's `declares_attributes` in the committed IR (`_built/<module>.s0ma.json`, shipped as package data); members declaring `mcp_uri:<uri>` enter the catalog under their **URI** (the served-surface naming rule), explicitly mapped plumbing (`load_doc` → `guide_doc_loader`) keeps its established catalog name, and everything else (data cells, helpers, `version_document`) stays global-registry-only, exactly matching the pre-conversion catalog scope. Bridged specs are re-stamped with the package conventions (`version=_package_version()`, `module_path="s0ma_mcp.<module>"`); dependency edges are translated through the same name map and edges onto non-cataloged components are dropped (the documented F-M0-6/spike deltas — `self_model_resource` loses its `self_registry` edge, `version_resource` its `version_document` edge — the D-6 graph-closure and set-equality gates stay green at every commit). The URI⇄identifier mapping is therefore authored once, in the `.s0ma` source (`declares_attributes`), and read from the IR — no hand-maintained table. Catalog names (URIs + `guide_doc_loader`) are disjoint from the built module's global-registry names by construction, which keeps the self-registry/global-registry separation test exact.

## Decision 2 — `built_at` and artifact path portability: fix the writers (rule 10), do not normalize in the gate

M0 flagged the manifest's run-varying `built_at` (F-M0-8). With the code in front of us the defect is wider: the manifest also records `build_dir` as an **absolute machine path** (`str(S0maProject.build_dir)` — `/Users/…`, `C:\…`) and `modules[].source` as the **as-passed** path (CWD-dependent, backslashes on Windows), and the IR + source map each embed `source_file` the same as-passed way. Every one of these is a literal INV-5 violation — "No emitted artifact may embed wall-clock time, randomness, **absolute machine paths**, or environment-dependent ordering" — and NFR-7 binds determinism **across** platforms ("building the same input on any supported OS yields byte-identical artifacts"). A committed build cannot carry any of them: the same rebuild on ubuntu/windows CI must reproduce the committed bytes exactly.

**Decided:** a disciplined s0ma-dsl change (plan rule 10, its own commit, with tests), the direct continuation of the Windows plan's WIN-M3 fix (which already moved IR `transpiled_file`/map `output_file` to basenames for exactly this invariant):

- **`built_at` is removed from the manifest writer.** `BuildManifest.built_at` defaults to `""`, `to_dict` emits the key only when non-empty, `build_manifest()` no longer stamps wall-clock, and `load_manifest` tolerates absence — old manifests (with the field) still load; new manifests omit it. INV-5 forbids the field's only honest value, so it goes; pinning a fake constant would keep schema noise with no information, and gate-side normalization would leave the package shipping an INV-5-violating artifact and turn the byte-equality gate into a semantic comparator that can mask real determinism regressions. The schema string stays `s0ma-build-manifest@1` with the field documented optional — a pre-1.0 relaxation under INV-4's allowance, carried in the CHANGELOG; the only in-tree reader (`load_manifest`) updates in the same commit, and manifests are project-local regenerable artifacts, not cross-version exchange formats.
- **Recorded paths become project-root-relative POSIX** when a `[tool.s0ma]` project is resolved: manifest `modules[].source` and `build_dir`, IR `source_file`, and source-map `source_file` all record e.g. `s0ma_src/resources.s0ma` / `src/s0ma_mcp/_built` with forward slashes on every OS. Synthetic-fallback builds (no project) keep the legacy as-passed form (there is no root to be relative to). Diagnostics keep the as-passed invocation paths (user-facing, ephemeral — not artifacts).
- **The one reader that resolved recorded sources resolves them against the project root** (`doctor._module_statuses`, which powers `s0ma doctor` and the `project_status` tool): relative manifest entries resolve against `project.root` instead of the CWD — fixing, as a bonus, the latent freshness bug where `project_status` only matched manifest entries when invoked from the same CWD the build ran in.

The `selfhost-build` equality stage is therefore a **pure byte comparison** — no normalization, no special-cased files — which is what makes it a standing cross-platform determinism regression test (P-4) and not just a "did you forget to commit" check.

## Decision 3 — MCP metadata carrier direction for M4 (§1.3)

Recorded for M4, from what M1 learned inside the build machinery: the intended carrier is **option (a) — a small, typed emitter pass-through of `declares_attributes` into the emitted runtime `metadata=` dict** (today the field parses, strict-checks, and rides the IR but never reaches the runtime registration — F-M0-7). M1's catalog bridge already proves the data path end to end by reading `mcp_uri:` entries from the committed IR and stamping them into bridged specs' `metadata["mcp_uri"]`, so M4's registry-derived `create_server()` can be written against `metadata["mcp_uri"]` regardless of which side supplies it: if the emitter pass-through lands (one emitter function + golden regeneration, IR unchanged), the bridge's IR lookup simply becomes redundant and dies; if M4 judges the emitter change disproportionate, the IR-reading bridge generalizes into §1.3's option (b) sidecar (it is data read from a committed artifact, not registration logic). `ToolAnnotations` for tools (M3) ride the same channel as additional `declares_attributes` namespaces (e.g. `mcp_tool_annotations:read_only`), or the option-(b) table if (a) does not land — M3 should author them as `declares_attributes` from the start so the IR carries them either way.

## Decision 4 (SH-M4 addendum) — the single bootstrap module is the package `__init__.py`; the carrier resolved as "catalog metadata, fed by the IR bridge"

Recorded at M4, completing FR-MCP-11's end state. Three resolutions:

**(a) The one handwritten module is `src/s0ma_mcp/__init__.py`** — `components.py` and `server.py` are retired into it, not the other way around. This is the only choice consistent with Decision 1's own reasoning: the runtime aliasing block must execute on *package import* (it is what makes `import s0ma_mcp.resources` resolve at all), `__init__.py` is the only module that runs then, and L1's rejection already named `__init__.py` as "the one file FR-MCP-11's end state still needs handwritten logic in". A server.py survivor would have left a second handwritten module (`__init__.py` cannot be emitted — the build owns only `_built/__init__.py` — and a namespace package was rejected: PEP 420 packages execute nothing on import, so the aliasing would never run and `import s0ma_mcp.tools` would break). Costs accepted and mitigated: the console script moves to `s0ma_mcp:main` (a pyproject edit), and `sys.modules["s0ma_mcp.server"]` is kept as a **runtime alias of the bootstrap module itself**, so the documented 0.6.x import forms (`from s0ma_mcp.server import create_server/main`) and any stale installed console-script shim keep working; the canonical typed import is now `from s0ma_mcp import create_server`. The emitted modules' back-references to the package (`requires: [s0ma_mcp:self_model_document]` etc.) import attributes of the *partially initialized* package during `bootstrap_imports`, which is why the bootstrap module defines all self-model plumbing ABOVE the bootstrap call — an ordering contract documented in the module docstring.

**(b) The §1.3 carrier question is closed as option (b'): catalog metadata, fed by the IR-reading bridge.** Decision 3's emitter pass-through was NOT needed: M1–M3 already proved every `mcp_*` fact flows `declares_attributes` → IR → bridge → `ComponentSpec.metadata`, and M4's factory is written against that metadata alone — relocating the IR read into the emitted `metadata=` dict would change no observable behavior, so the smaller system won. M4 added the last two namespaces the served surface needed (`mcp_prompt_title:`, `mcp_mime_type:` — attribute values may contain spaces; everything after the first colon is the value) and moved the served tool descriptions to the declarations themselves (the old wrapper docstrings, byte-exact — A-7 now applies to tools too). The pass-through (or better, F-M3-3's first-class declaration `metadata:` field) remains the recorded direction if a future consumer needs the facts at runtime WITHOUT this package's bridge.

**(c) The factory derives; one binding-layer mutation was required.** `create_server()` iterates the insertion-ordered catalog (the registry's authoritative feed — a test pins catalog set == registry set) and binds each component by its metadata kind. FastMCP derives tool schema titles (`<name>Arguments`/`<name>DictOutput`) from the bound callable's `__name__`, and tool declarations are `_tool`-suffixed by the registry-disjointness rule — so the factory stamps the MCP serving name onto the callable at binding time (`_served_as`, an idempotent in-place rewrite exactly parallel to `normalize_docstring`); without it the served schemas could not stay byte-identical to 0.6.x (D-5). The bridge/self-model machinery stays handwritten in the bootstrap module deliberately: converting it to `.s0ma` would require a built module to observe its sibling built modules and the bootstrap's return value mid-bootstrap (ordering the manifest cannot express), and D-1 explicitly tolerates plumbing in the bootstrap module.

## Consequences

- `packages/s0ma-mcp` is a real `[tool.s0ma]` project; the edit loop for converted surfaces is: edit `s0ma_src/<m>.s0ma` → `uv run s0ma --project-root packages/s0ma-mcp build packages/s0ma-mcp --mode release` (the D-6 ramp completed at SH-M5: `dev` through M2, `strict` from M3, `release` from M5 — release mode also renders the doc-ref/doc-guide artifacts into `_built/docs/`) → run the gate → commit source + `_built/` together. A red `selfhost-build` stage means a missing rebuild+commit or a determinism regression — both are real failures, never flaky.
- The self-model's plumbing entries change shape as documented (F-M0-6/F-M0-7 deltas): `load_doc` serves as `guide_doc_loader` at PRESENTATION (was INFRASTRUCTURE), bridged specs carry contracts from `expects:`/`guarantees:` (richer than before) and `metadata["mcp_uri"]`, and two plumbing dependency edges thin out. The MCP-served surface itself — names, URIs, schemas, descriptions, contents — is byte-/set-identical (D-5; the suite and the equality of intents/docstrings enforce it).
- `.s0ma.cache/` may appear inside `_built/` on cached local builds: gitignored (already covered by the root `.s0ma.cache/` pattern), excluded from the wheel, and absent from CI (the stage builds `--no-cache`).
- `s0ma-mcp`'s wheel now ships emitted artifacts (`.py`, `.s0ma.json`, `.s0ma.map`, `build.s0ma.json`, `build.s0ma.pyi`) as package payload — the IR in the wheel is load-bearing (the catalog bridge reads it), the rest document the build and serve M4's bootstrap.
- ruff excludes `src/s0ma_mcp/_built` (generated code carries the DSL's single-line registered strings, which exceed human line-length rules by design); mypy `--strict` does **not** exclude it — emitted code meets the same typing gate as handwritten code (D-2/INV-8).
