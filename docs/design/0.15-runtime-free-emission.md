# 0.15 Design Note: Runtime-Free Emission

**Status:** design review pending — did not ride the 0.15.x releases; retargeted to the
0.16 design cycle (2026-08-10). Deliberately not implemented in 0.14.
**Origin:** 0.14 M2 host-reality verification
**Outcome (2026-08-28):** the 0.16 retarget **expired** — 0.16.x and 0.17.0 both shipped
without it. The `0.15` in this filename is historical, not a target; the file is kept for
the problem statement below, not as a schedule. The round is still open, but it is no
longer open-ended: the **emitted-import decision of 2026-08-17** settled that bare
cross-module imports stay and that a flat build plus `s0ma.bootstrap.bootstrap_imports` is
the *only* emitted-import contract, so the declared-build-layout question folds **into**
this runtime-free-emission profile rather than standing beside it as a second axis. The
current normative statement of what is left — emitted modules still import
`s0ma_dsl.runtime_bridge.registration` — is PRD FR-CORE-9 and INV-9
([`references/s0ma-prd.md`](../../references/s0ma-prd.md), v1.7 revision row), pinned by a
failing-forward boundary test
([`packages/s0ma-dsl/tests/test_runtime_free_bootstrap.py`](../../packages/s0ma-dsl/tests/test_runtime_free_bootstrap.py)).
Read the open questions below as this round's agenda, not as undecided packaging policy.

## Problem

Every generated module currently imports `s0ma-core` registration/decorator types and
the `s0ma-dsl` runtime bridge. That is honest and useful for a load-bearing live model,
but it means a host that copies generated Python without declaring and installing both
runtime distributions will fail at import time.

0.14 detects this in two places: emitting commands warn when the host omits those PEP
621 dependencies, and explicit `verify-host` proves declared/installed/import reality
under the app's actual interpreter. It does not change emission semantics in flight.

## 0.15 decision to make

Evaluate an explicit, versioned build profile that can emit runtime-free Python while
preserving canonical IR as a separate artifact. The design must answer:

- which registration, contract, and introspection behavior is intentionally removed;
- whether the profile is per build or per module, and how it is recorded in the manifest;
- whether runtime-free output can still satisfy any s0ma gate, or is an export-only form;
- how generated imports, stubs, source maps, drift hashes, and self-context differ;
- whether mixed runtime-backed/runtime-free module graphs are forbidden;
- the schema/version migration and wheel-size/performance evidence.

## Non-goals

0.14 will not conditionally strip imports, vendor the runtime, catch `ImportError`, or
pretend missing runtime packages are optional. Those shortcuts would change the
load-bearing semantics without a versioned contract and would make host verification
less truthful.
