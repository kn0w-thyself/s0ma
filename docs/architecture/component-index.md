## How to read the tables

**Component** is the id this documentation addresses it by, which is its import path with a prefix. **Kind** is what sort of thing it is and **Layer** is where it sits: a presentation component may reach an application one and an application one may reach the framework, never the other way round, and that rule is checked at build time rather than asserted here. The two columns answer different questions and their answers may read the same — a framework-kind component sitting in the framework layer is the ordinary case, not a repetition.

**Visible** is the declared visibility, or `not declared` where the registration carries none. **What it is for** is the component's own stated intent, quoted rather than rewritten — every registered component has to say what it is for, and this is what each of them said.
